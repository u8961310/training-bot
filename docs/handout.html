第 0 關

學會問：卡關時請 Gemini 當你的程式小老師

約 5 分鐘

等一下的 Apps Script（GAS）畫面都是程式碼，看不懂很正常。先學會怎麼問 Gemini，後面看到藍色的「問 Gemini」框，就是提醒你這時可以拿哪一段提示詞來用。

0

先開好 Gemini 分頁

  1. Chrome 另開一個分頁到 gemini.google.com，用個人 Gmail 登入
  2. 這個分頁一直開著，等一下哪一步看不懂，就切過來問
這裡是「跟 Gemini 聊天」的網頁；第 3 步的 aistudio.google.com 是幫小秘書「拿 API key」的地方，兩個不一樣。

好提示詞＝交代代課老師的四句話

① 角色你是誰
「你是很有耐心的 Apps Script 老師」
② 任務要做什麼
「告訴我這個錯誤怎麼解決」
③ 規則哪些不能做
「我不會寫程式，不確定就說不確定」
④ 格式交回什麼樣子
「一步一行，寫出要點哪個按鈕」
太模糊我的程式壞了怎麼辦？
→ Gemini 不知道你在哪一步、出了什麼錯，只能給一堆通用建議。
四句話都有你是 Apps Script 老師，我執行 setup 出現下面的錯誤，我不會寫程式，請一步一步告訴我在畫面上點哪裡。
→ 回答具體，照著做就好。
最重要的是第 ③ 句。AI 最常犯的錯是「很有自信地亂編」，先說清楚你的程度、要它不確定就講，能少掉一大半麻煩。

求救提示詞｜執行出現紅字時

求救提示詞（第 6、7 步最常用到）
你是很有耐心的 Google Apps Script 老師，我是完全不會寫程式的老師。
我在 Apps Script 執行「setup」函式時出現下面的錯誤。

請你：
1. 用一句白話說明這個錯誤是什麼意思。
2. 一步一行，告訴我在畫面上要點哪裡、改什麼。
3. 除非真的必要，不要叫我改程式碼；要改的話，告訴我改哪一行、整行改成什麼。
4. 不確定原因就直接說不確定，不要亂猜。

---- 錯誤訊息 ----
（把執行記錄裡的紅字整段複製貼上）
貼給 Gemini 之前看一眼：錯誤訊息裡如果有 Token、AIza… 開頭的 key，先刪掉再貼。鑰匙只放在指令碼屬性，不給任何人，AI 也一樣。

解說提示詞｜想看懂一段程式

解說提示詞
你是 Google Apps Script 老師。下面是一段程式，請用老師聽得懂的話，
分段說明每一塊在做什麼，每段不超過兩句。只要解釋，不要修改程式。

（在 Apps Script 反白一個函式，例如 function setup() { … } 整段，複製貼上）
想改早報時間、請 Gemini 寫新工具，或用提示詞從零生出一支小秘書，都在最後的進階篇。

第 1 關

拿鑰匙：幫小秘書辦電話、裝腦袋

約 15 分鐘
1

開一個 LINE 官方帳號（小秘書的電話）

  1. 電腦開 manager.line.biz，用你的 LINE 帳號登入
  2. 按 建立，帳號名稱填「研習小秘書」，業種隨意選（例如「教育」）
  3. 建好後進入這個帳號，按右上角 設定 → 左邊 Messaging API → 啟用 Messaging API
  4. 「服務提供者」選 建立新的，名稱填你的名字即可 → 同意 → 確定
畫面顯示 Channel ID、Channel secret，就代表啟用成功。
2

拿第一把鑰匙：Channel access token

  1. 同一頁點連結進入 developers.line.biz（LINE Developers），找到剛剛的 channel
  2. 上方分頁切到 Messaging API，捲到最下面 Channel access token
  3. 按 Issue，出現一長串英數字，按旁邊的複製圖示
  4. 先貼在電腦的「記事本」暫放，第 5 步會用到
LINE Developers ─ Messaging API
Channel access token (long-lived)
eyJhbGciOiJIUzI1NiJ9.xxxxxxxx…… Issue
順便在同一頁把 Auto-reply messages（自動回應訊息）設成「停用」，不然每次傳訊息，LINE 都會搶著回一句罐頭訊息。
3

拿第二把鑰匙：Gemini API key（小秘書的腦袋）

  1. 開 aistudio.google.com，用個人 Gmail 登入；第一次會要你同意條款
  2. 點 Get API key → Create API key（要選專案就選預設的）
  3. 複製那串 AIza… 開頭的字，一樣先貼到記事本
記事本裡現在有兩行：一行 LINE token、一行 AIza…。
免費方案不用綁信用卡。完整的 key 只會顯示一次，忘了複製的話，刪掉重建一個就好。

第 2 關

搬進家具：把程式放進 Google Apps Script

約 15 分鐘

Apps Script 是 Google 免費提供的「雲端小電腦」，程式放上去就會 24 小時待命，不用開著你的電腦。

4

建立專案，貼上程式

  1. 開 script.google.com → 左上角 新專案
  2. 點上方「未命名的專案」，改名為「研習小秘書」
  3. 編輯區已經有幾行預設程式碼：點進去按 Ctrl+A 全選，刪掉
  4. 另開分頁到 github.com/u8961310/training-bot → 點 docs → training-bot.gs，按程式碼右上角的 ⧉ Copy raw file 複製全部
  5. 回到 Apps Script 編輯區，按 Ctrl+V 貼上
  6. 按 Ctrl+S 存檔
第一行是 // ===== Config.js =====，存檔後沒有跳出紅色錯誤訊息。
這支程式是寫好的完整版，今天直接複製就好。想知道怎麼用提示詞請 Gemini 從零寫出來，看進階篇。
5

把兩把鑰匙放進保險箱（指令碼屬性）

  1. 左側點齒輪 ⚙ 專案設定
  2. 確認 時區 是「(GMT+08:00) 台北」，不是的話改過來
  3. 捲到最下面 指令碼屬性 → 新增指令碼屬性，照下表加兩行（左邊一字不差，大寫、底線都要對）
  4. 按 儲存指令碼屬性
專案設定 ─ 指令碼屬性
LINE_CHANNEL_ACCESS_TOKEN（第 2 步那串）
GEMINI_API_KEY（第 3 步 AIza… 那串）
鑰匙放在這裡，而不是寫在程式碼裡，這樣哪天要把程式分享給別人，也不會連鑰匙一起送出去。
6

執行 setup，讓它自己建日曆與試算表

  1. 回到 <> 編輯器，上方工具列的函式下拉選單選 setup → 按 ▷ 執行
  2. 跳出「需要授權」→ 審查權限 → 選你的 Gmail
  3. 看到「Google 尚未驗證這個應用程式」→ 點左下 進階 → 前往「研習小秘書」（不安全） → 允許
為什麼寫「不安全」？因為這支程式是你自己的，沒送 Google 審查。它要的權限（日曆、試算表、雲端硬碟、寄信、連外網）都是給你自己的小秘書用的。
執行記錄
已建立日曆：研習 已建立試算表：https://docs.google.com/spreadsheets/d/…… 已建立講義資料夾：https://drive.google.com/drive/folders/…… 早報觸發器：每天 7:30 左右 ⚠️ 還沒設定：ALLOWED_USER_IDS
看到上面五行就對了。最後一行的 ⚠️ 是正常的，第 11 步才會補上。
想知道 setup 到底做了什麼？在編輯區反白整個 function setup() { … }，用解說提示詞請 Gemini 解釋。執行跳紅字就用求救提示詞。
7

執行 testExtract，確認腦袋會動

  1. 下拉選單改選 testExtract → ▷ 執行
  2. 等 3–10 秒，看下方執行記錄
記錄裡出現一段有 "title"、"date"（9 月 28 日）、"start": "19:00" 的文字，就代表 Gemini 讀得懂公告。
如果出現 API key not valid：回第 5 步檢查 GEMINI_API_KEY 有沒有貼完整、前後有沒有多空白。
出現其他紅字看不懂？用求救提示詞，把執行記錄的紅字貼給 Gemini（先刪掉裡面的鑰匙）。

接上電話線：讓 LINE 找得到小秘書

約 15 分鐘
8

部署成「網頁應用程式」，拿到門牌網址

  1. 編輯器右上角 部署 → 新增部署作業
  2. 「選取類型」旁的齒輪 → 選 網頁應用程式

  3. 把下面的 Use webhook 開關打開（變綠色）
旁邊的 Verify 按下去可能顯示錯誤（Google 會多轉一次網址），不用理它，以第 10 步實測為準。

把自己加進白名單

用提示詞，請 Gemini 從零生出一支小秘書

約 60 分鐘

今天複製的 training-bot.gs 有將近 900 行，一段提示詞叫 Gemini 一次寫完不切實際。訣竅是先講好共同規格，再分 4 段慢慢加，每一段都能跑、都有檢查點，壞了也知道壞在哪一段。

開始前準備（跟主線共用鑰匙，但另開一個專案）

  1. script.google.com → 新專案，改名「小秘書（自己生）」；專案設定的時區一樣改成台北
  2. 指令碼屬性照第 5 步加 LINE_CHANNEL_ACCESS_TOKEN、GEMINI_API_KEY，ALLOWED_USER_IDS 先不要填，第 1 段要用設定模式測試
  3. Gemini 開一段新對話，4 段提示詞都在同一段對話裡接著貼，它才記得前面寫過什麼
一個 LINE 官方帳號只能接一個 Webhook 網址。練習時把 Webhook 換成新專案的網址，主線的小秘書會暫停；練完記得換回第 8 步的網址。想兩支同時用，就再開一個 LINE 官方帳號。

每一段貼好之後：更新部署

主線只部署一次，但這裡每段都會改程式，改完要發布新版本，LINE 才會用到新程式：

  1. 第一次（第 1 段）：照第 8 步 新增部署作業，再照第 9 步把新網址填進 LINE Webhook
  2. 之後每段：部署 → 管理部署作業 → 右上鉛筆（編輯）→ 版本選 新版本 → 部署。網址不會變，LINE 不用重設

共同規格｜第一則先貼這段

共同規格提示詞
你是 Google Apps Script 老師，我是不會寫程式的老師。接下來我會分 4 段，請你幫我寫一支「研習 LINE 小秘書」：
老師把研習公告傳給 LINE 官方帳號，AI 整理成卡片，按確認後寫進 Google 日曆，並在早上提醒。
這一則先不要寫程式，記住下面的共同規格，回我「了解」就好。

【共同規格】
1. 全部寫在同一個 .gs 檔，不使用外部函式庫。
2. 金鑰和設定一律從「指令碼屬性」讀，絕對不可以寫在程式碼裡。屬性名稱固定：
   LINE_CHANNEL_ACCESS_TOKEN、GEMINI_API_KEY、ALLOWED_USER_IDS（多個用半形逗號分隔）、CALENDAR_ID、SHEET_ID
3. 時區一律 Asia/Taipei。
4. 這些函式名稱固定、一字不差：doGet、doPost、lineReply、geminiExtract、testExtract、setup、dailyDigest、setupTrigger。
5. 回覆 LINE 用 reply API（https://api.line.me/v2/bot/message/reply）；只有 dailyDigest 可以用 push API。
6. 每一段都在前一段的程式上「增加功能」，每次都給我「完整的程式碼」，我會全選覆蓋貼上。
7. 每一段加中文註解，重要步驟用 console.log 印出進度。

1第 1 段｜骨架：接上 LINE、擋住陌生人

第 1 段提示詞
【第 1 段：骨架】請照共同規格寫：
1. doGet：瀏覽器打開網址時，回傳純文字「training-bot OK」。
2. doPost：接收 LINE Messaging API 的 webhook，逐一處理 events；不管成功失敗，最後都回傳文字「OK」。錯誤用 console.error 記錄，不要讓程式整個停掉。
3. lineReply(replyToken, messages)：共用的回覆函式，messages 可以是一則或多則。
4. 白名單：讀 ALLOWED_USER_IDS。
   - 如果是空的：不論對方傳什麼，都回覆
     「🔧 設定模式
     你的 userId：
     （對方的 userId）

     把它填進指令碼屬性 ALLOWED_USER_IDS 就能開始用。」
   - 不在名單裡：不回覆，直接忽略。
   - 在名單裡：先回覆「收到：」加上對方傳的文字（之後的段落會換成真正的功能）。
貼上存檔 → 照第 8 步部署、第 9 步換 Webhook → 瀏覽器開網址看到 training-bot OK → LINE 傳「你好」收到「🔧 設定模式」→ 把 userId 填進 ALLOWED_USER_IDS → 再傳「測試」收到「收到：測試」。
